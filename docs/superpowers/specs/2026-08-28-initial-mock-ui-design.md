# 꿈꾸는 키친 통합 판매채널 관리 웹앱 초기 Mock UI 설계

## 1. 목표

꿈꾸는 키친 직원이 여러 판매채널의 상품과 옵션 상태를 한곳에서 확인하고, 품절 또는 판매재개 업무 흐름을 안전하게 연습·검토할 수 있는 Netlify 배포형 초기 웹앱을 만든다.

이번 버전은 실제 쇼핑몰을 제어하지 않는다. 모든 상품, 판매상태, 실행 결과와 작업 이력은 Mock 데이터이며 화면에서 이를 명확히 알린다.

## 2. 확정 범위

- 상품명, 이카운트 품목코드, 옵션코드 검색
- 상품 목록과 상품 상세 확인
- 상품 전체 또는 개별 옵션 선택
- 판매채널별 현재 상태 표시
- 채널별 품절·판매재개 Mock 실행
- 사방넷 그룹 품절·판매재개 Mock 실행
- 전체 판매처 품절·판매재개 Mock 실행
- 실행 전 대상 상품, 옵션, 채널, 명령을 확인하는 확인창
- 실행 후 채널별 성공·실패·미실행 결과 표시
- Mock 작업 이력 조회
- PC와 모바일에서 사용할 수 있는 반응형 화면
- Netlify에서 빌드·배포 가능한 프로젝트 구성

## 3. 판매채널 규칙

### 사방넷 연동 채널

- 에이블리
- 지그재그
- 토스쇼핑
- NS홈쇼핑
- 테무
- e-제너두

사방넷 API의 실제 전파 방식은 확인되지 않았으므로 `사방넷 연동 검증중`으로 표시한다. V1의 버튼은 화면 흐름을 검증하기 위한 Mock 실행만 수행한다.

### 직접 관리 채널

- 네이버 스마트스토어
  - 품절 Mock 값: 재고수량 0
  - 판매재개 Mock 값: 재고수량 999
- 오늘의집
  - 품절 Mock 값: 재고상태 `품절`
  - 판매재개 Mock 값: 재고상태 `판매중`
  - 사용상태나 재고 숫자를 바꾸는 표현은 사용하지 않는다.
- 카페24
  - `연동 준비중`으로 표시한다.
  - 필드와 제어 방식이 확정되지 않았으므로 품절·판매재개 실행 대상에서 제외한다.
  - 전체 실행 결과에는 `미실행 · 연동 준비중`으로 표시한다.

## 4. 정보 구조와 화면

웹앱은 하나의 반응형 관리 화면 안에서 다음 메뉴를 제공한다.

1. **대시보드**
   - 관리 상품 수, 판매중 옵션, 품절 옵션, 확인 필요 건수
   - 최근 Mock 실행 결과와 채널 상태 요약
2. **상품 관리**
   - 상품명·이카운트 코드 통합 검색
   - 상품 목록에서 상품을 선택하면 옵션과 판매채널 상태 표시
   - 상품 전체와 개별 옵션을 전환해 제어
3. **작업 이력**
   - 실행일시, 실행 직원, 상품코드, 상품명, 옵션, 명령, 대상, 결과 확인

별도 API 설정, 직원관리, 로그인 화면은 이번 범위에 포함하지 않는다.

## 5. 주요 업무 흐름

### 상품 또는 옵션 제어

1. 직원이 상품명이나 이카운트 코드를 검색한다.
2. 검색 결과에서 상품을 선택한다.
3. 상품 전체 또는 특정 옵션을 선택한다.
4. 채널별 상태를 확인한다.
5. 개별 채널, 사방넷 그룹 또는 전체 판매처의 품절·판매재개를 선택한다.
6. 확인창에서 상품, 옵션, 명령과 대상 채널을 확인한다.
7. `Mock 실행`을 선택한다.
8. 채널별 결과를 확인한다.
9. 실행 내역이 현재 브라우저 세션의 작업 이력에 추가된다.

### 안전장치

- 버튼을 누르는 즉시 상태를 바꾸지 않는다.
- 모든 변경은 확인창의 두 번째 동작 후 실행한다.
- 확인창과 결과 화면에 `Mock 실행 · 실제 판매처에는 반영되지 않음`을 표시한다.
- 일부 채널 실패를 전체 성공으로 표시하지 않는다.
- 카페24는 성공으로 가장하지 않고 미실행으로 기록한다.

## 6. Mock 데이터와 상태

샘플 상품은 브랜드, 이카운트 상품코드, 상품명, 옵션 목록으로 구성한다. 각 옵션은 고유 이카운트 옵션코드를 가진다.

채널 상태는 다음 값만 사용한다.

- `ON_SALE`: 판매중
- `SOLD_OUT`: 품절
- `PENDING`: 연동 준비중 또는 확인 필요

Mock 실행 결과는 다음 값으로 구분한다.

- `SUCCESS`: Mock 상태 변경 완료
- `FAILED`: 실패 사유와 함께 표시
- `SKIPPED`: 미확정 연동으로 실행하지 않음

화면 상태는 브라우저 메모리에서만 유지한다. 새로고침하면 초기 Mock 데이터로 돌아오며, 실제 DB 구조를 확정하거나 브라우저 저장소를 운영 DB처럼 사용하지 않는다.

## 7. 화면 표현 원칙

- 개발 지식이 없는 직원도 현재 상품, 옵션과 명령 대상을 한눈에 이해할 수 있게 한다.
- 상품 검색과 품절·판매재개 동작을 첫 화면의 중심에 둔다.
- 판매중은 초록, 품절은 주황·빨강, 준비중은 회색 계열로 구분하되 텍스트를 함께 표시한다.
- 품절과 판매재개 버튼은 색상뿐 아니라 명확한 동사로 구분한다.
- 모바일에서는 표를 억지로 축소하지 않고 카드형 목록으로 재배치한다.
- 회사명과 서비스명은 `꿈꾸는 키친 · 통합 판매채널 관리`로 표시한다.

## 8. 기술 구성

- Vite
- React
- TypeScript
- Vitest와 Testing Library
- CSS 기반 반응형 UI
- Netlify 정적 배포

서버, DB, 인증, Netlify Functions, 외부 API 클라이언트는 V1에 추가하지 않는다. 향후 실제 연동 시 화면과 Mock 실행 함수를 유지하면서 채널별 어댑터와 서버 기능을 별도 추가할 수 있도록 업무 규칙을 UI 컴포넌트와 분리한다.

## 9. 검증 기준

- 상품명과 이카운트 코드로 검색할 수 있다.
- 상품 전체와 특정 옵션을 선택할 수 있다.
- 네이버 품절·판매재개 결과가 각각 0과 999 규칙을 보여준다.
- 오늘의집 품절·판매재개 결과가 재고상태 규칙을 보여준다.
- 카페24가 실행 성공으로 표시되지 않는다.
- 전체 실행 전 확인창이 반드시 표시된다.
- 실행 결과가 채널별로 분리되어 표시된다.
- 실행 후 Mock 작업 이력이 추가된다.
- 실제 연동이 아니라는 안내가 주요 실행 화면에 보인다.
- 자동 테스트, 정적 검사와 Netlify용 배포 빌드가 모두 성공한다.
- PC와 모바일 크기에서 핵심 기능을 사용할 수 있다.

## 10. 이번 버전에서 제외하는 사항

- 실제 이카운트 재고 자동 동기화
- 실제 네이버, 오늘의집, 카페24 또는 사방넷 API 호출
- 카페24 제어 필드 확정
- 사방넷 전파 방식 확정
- 실제 사용자 로그인과 권한 분리
- 실제 DB 및 영구 작업 이력
- API 키 저장 방식
- 자동 품절 조건

제외 항목은 사용자 확인과 기술 검증을 거친 후 별도 업그레이드로 설계한다.
